# Mixing knowledge library — store schema (v1)

One store, read by the desktop app (Library page), the `wing library` CLI,
the Python API `wing_parser.library`, and automix. Never fork the format:
change it here, in `wing_parser/library/schema.py`, and in the tests together.

## Layout

```
knowledge/library/
  SCHEMA.md            this file
  topics.yaml          topic taxonomy (id + en/vi labels)
  sources.yaml         publisher allow-list (reputable sources)
  entries/<id>.yaml    one entry per file, UTF-8, LF
  media/<id>/<file>    generated diagrams (PNG + SVG source) for that entry
  history/<id>.jsonl   append-only revision log, written ONLY by the store API
```

Two layers. **Shipped** = this folder (bundled into the exe). **User** =
`~/.config/wing-skill/library/` in the exe (in a repo checkout the two are
the same folder). Readers see shipped ∪ user, the user entry winning by id;
every save writes the user layer and its `history/`. A new exe therefore
brings new and updated shipped entries, except ones the user has edited.
`WING_LIBRARY_DIR` overrides the user layer.

## Entry keys

| key | required | type | notes |
|---|---|---|---|
| `id` | yes | str | kebab-case `^[a-z0-9]+(-[a-z0-9]+)*$`, equals the file stem, never changes |
| `title` | yes | str | English |
| `title_vi` | no | str | Vietnamese title |
| `topic` | yes | str | one id from `topics.yaml` |
| `tags` | yes | map | `instrument`, `genre`, `technique`, `event` — each a list of kebab-case strings (may be empty) |
| `summary` | yes | str | 1–3 sentences, own words |
| `summary_vi` | no | str | Vietnamese summary (non-empty when present). Mixer/audio technical terms stay in English (EQ, gain, fader, compressor, threshold, feedback), as in the app's bilingual UI |
| `body` | yes | str | Markdown, own words. Never copied text; at most one short quote (<15 words) in quotation marks with its source |
| `body_vi` | no | str | Vietnamese body, Markdown, same rules as `body` (own words, sourced by the same `sources`); technical terms stay English as above |
| `rule` | no | map | structured data for automix/advisory (free shape; see below) |
| `sources` | yes, ≥1 | list | see Sources |
| `media` | no | list | see Media |
| `confidence` | yes | enum | `established` (standards, manuals, physics) · `common-practice` (several reputable sources agree) · `contested` (sources disagree — body must say how) |
| `status` | yes | enum | `draft` · `reviewed` · `retired` (retired = hidden by default, never deleted) |
| `revision` | yes | int | starts at 1, +1 on every save through the store API |
| `updated_at` | yes | str | ISO 8601 with timezone |
| `updated_by` | yes | str | person name, OS user, or `agent:<name>` |

## Sources

Each item: `title` (req), `publisher` (req), `kind` (req: `article` ·
`book` · `paper` · `manual` · `standard` · `video` · `course`), `url`
(req unless `kind` is `book`; http/https), `author`, `year`, `accessed`
(req, `YYYY-MM-DD`), `locator` (page / section / chapter / `mm:ss`), `doi`,
`isbn`.

- An entry with no source is **blocked on save** (UI and CLI) and
  **flagged `unsourced`** when a hand-edited file is loaded.
- A source whose `publisher` is not in `sources.yaml` is a warning
  (`unvetted-source`), shown on the entry.

## Media

Each item has `kind`:

- `diagram` — a file under `media/<id>/` generated by
  `scripts/library_diagrams.py`; `path` (relative to `media/<id>/`),
  `caption`, `license: CC0-1.0`, `attribution: "Generated for wing-parser"`,
  `generated_by: scripts/library_diagrams.py:<function>`.
- `image` — an external image under a clear licence, stored **as a link**
  (not re-hosted): `url` (the file page, e.g. Wikimedia Commons), `caption`,
  `license` (SPDX-like: `CC-BY-SA-4.0`, `CC-BY-4.0`, `CC0-1.0`,
  `public-domain`), `attribution` (author as the licence requires).
- `video` — a link to the original, never downloaded: `url`, `title`,
  `channel`, optional `timestamp` (`mm:ss`), `caption`.

Any media item may carry `caption_vi` (optional, non-empty when present): the
Vietnamese caption, same term convention as `summary_vi`.

## `rule` (optional, for automix)

A mapping (the library validates only that). Shape agreed with the automix
lane 2026-11-09 — automix reads entries whose `kind` it knows and owns the
per-kind `params` schema (`wing_parser/automix/`). Kinds: `eq_target`,
`eq_bounds`, `masking_pair`, `fader_offset`, `gain_staging`, `comp_start`,
`gate_start`, `reverb_genre`, `delay_genre`, `send_level`, `fx_model`.
A `rule` without `kind` is a human-readable starting window only.
Genre tag values shared with automix: `pop`, `rock`, `ballad`, `jazz`,
`edm`, `bolero`, `speech`.

```yaml
rule:
  kind: comp_start
  applies_to: {source_type: [vocal.lead], genre: [pop]}
  params:
    hpf_hz: [80, 120]          # [low, high] range = a starting window
    comp_ratio: [2, 4]
  notes: "starting point, adjust by ear"
```

## History line (`history/<id>.jsonl`)

`{"rev": 3, "at": "...", "author": "...", "action": "create|edit|retire|restore",
"note": "why", "snapshot": {<full entry after the change>}}` — one JSON
object per line. Diffs are computed between consecutive snapshots.
